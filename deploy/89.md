# 89 生产部署（本 fork）

目标机：`sub2api-89`（与 sub2api 同机）。源码仓：`https://github.com/wuxiran/codex-proxy-rs`。
安装目录：`/opt/codex-proxy-rs`。数据面只给本机 sub2api 用，不把管理端和 PostgreSQL/Redis 暴露到公网。

## 端口与隔离

| 服务 | 宿主机 | 说明 |
| --- | --- | --- |
| CPR HTTP | `127.0.0.1:18080` | sub2api 上游填 `http://127.0.0.1:18080/v1` |
| PostgreSQL / Redis | 不映射 | 仅 compose 内部网络 |
| 官方默认 `8080` | **禁止占用** | 已是 sub2api |

号池、OAuth、出口代理只放 CPR。sub2api 只保存一把 Client Key。

## 启动

在 `/opt/codex-proxy-rs`：

```bash
docker compose -f deploy/compose.yaml -f deploy/compose.89.yaml config --quiet
docker compose -f deploy/compose.yaml -f deploy/compose.89.yaml up -d --no-build --wait
curl -i http://127.0.0.1:18080/healthz
```

健康检查成功返回 `204`。管理端走 SSH 隧道，不要给 18080 配公网反代，除非另做 IP 限制。

```bash
ssh -J vps-xui -L 18080:127.0.0.1:18080 sub2api-89
```

浏览器打开 `http://127.0.0.1:18080`，用户 `admin@cpr.local`。

## 镜像

89 内存约 8GiB，不要在生产机编译 Rust。在能构建 `linux/amd64` 的机器上：

```bash
CPR_IMAGE=codex-proxy-rs:89-fork \
CPR_GIT_SHA="$(git rev-parse HEAD)" \
CPR_BUILD_TIME="$(date -u +%Y-%m-%dT%H:%M:%SZ)" \
docker compose -f deploy/compose.yaml -f deploy/compose.89.yaml build codex-proxy-rs
```

把 `codex-proxy-rs:89-fork` 传到 89 后 `docker load`，再执行上面的 `up --no-build`。

在线更新保持关闭，避免容器把二进制换成上游正式包。发我们自己的 Release 之前，不要打开 `CPR_ENABLE_SELF_RESTART`。

## 配置

`deploy/config.yaml` 由 `config.example.yaml` 复制，Git 忽略。PostgreSQL / Redis 密码各 `openssl rand -hex 24`；`admin.default_password` 至少 12 位且不含 `$`。已有数据目录后不要用模板覆盖该文件。

PostgreSQL 18 容器以 uid `999` 写数据目录。首次启动前需要：

```bash
chown -R 999:999 /opt/codex-proxy-rs/.runtime/postgres
chmod 0750 /opt/codex-proxy-rs/.runtime/postgres
```

应用数据和日志仍是 `10001:10001`。不要把 `.runtime/postgres` 也改成 `cpr` 用户，否则会出现 `mkdir: cannot create directory '/var/lib/postgresql'`。

## 401 复活

第三方接口：`https://zzledu.kdns.fr/revive-api`。只接受**已签名**的 Sub2API / CPA JSON，CPR 管理端导出不能直接上传。
脚本在仓库 `tools/revive/revive.py`，89 上可直接用系统 Python 3。

```bash
# 检测签名文件；有 401 则创建复活任务并写出恢复 JSON
python3 /opt/codex-proxy-rs/tools/revive/revive.py recover /path/to/signed.json --out /tmp/revived.json

# 把恢复结果导入本机 CPR（需要管理端 API Key）
CPR_ADMIN_URL=http://127.0.0.1:18080 \
CPR_ADMIN_API_KEY='...' \
python3 /opt/codex-proxy-rs/tools/revive/revive.py import-cpr /tmp/revived.json
```

签名文件含 OAuth 明文，请求会离开 89。不要把 `X-Revive-Task-Token` 或恢复 JSON 写进仓库、工单和普通日志。
